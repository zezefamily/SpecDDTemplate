# 测试规范与执行

所有新功能完成后必须编写/更新 test case，缺陷修复补充原问题的复现测试。用例关联 Spec 的 AC，记录前置条件、步骤/输入、预期与实际结果；覆盖正常流程、关键异常和边界条件。

## 按模块组织

模板自身测试在 tests/specdd/，共享测试准备在相应 helpers/fixtures；业务采用后使用 tests/<模块或主题>/ 或框架等效结构。多语言/多服务可分别保留测试目录，但在 PROJECT.md 记录统一入口。

用例必须可独立运行，不消费前序用例创建的数据；共享资源显式准备并清理。移动测试目录时同步测试发现入口，禁止空跑误报成功。

## 回归选择

- 增量：影响范围明确且独立，运行新用例、变更模块及直接关联链路。
- 全量：公共组件、跨服务契约、权限、数据结构、依赖、核心链路、测试基础设施或影响不明，执行项目所有适用检查。
- Spec 必须记录选择理由、环境、执行命令、范围与数量、结果、失败/跳过/未执行及剩余风险。
- 业务入口在 PROJECT.md 配置；不能照搬别的技术栈命令。隔离数据、模拟与真实服务分开说明；付费和生产写入按授权范围处理。

## 模板工具自测

全量：`python3 -m unittest discover -s tests/specdd -p 'test_*.py' -v`。
单主题：`python3 -m unittest discover -s tests/specdd -p 'test_lifecycle.py' -v`（或替换为具体文件）。
规范检查：`python3 tools/specdd.py check`。模板仓库的全量验证是工具全部测试、规范检查和文档链接检查；它们不是业务功能测试。
